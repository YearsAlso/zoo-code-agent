## Purpose

定义 agent 循环的推进方式与终止条件。该能力要求一次会话能从单个 prompt 出发，反复「问模型 → 执行工具 → 回灌观察」直到命中终止条件，并在每一轮留下**可被程序读取**的产出——使运行过程可断言，而不是只能端到端目视。

## ADDED Requirements

### Requirement: 循环 MUST 在终止条件之一命中时停止

循环 SHALL 在三类终止条件之一命中时停止：预算耗尽、截止期到达、模型不再请求工具调用。MUST NOT 在无终止条件的情况下无限推进。

#### Scenario: 模型不再请求工具时自然停止
- **WHEN** 模型返回的响应不含任何工具调用
- **THEN** 循环在该轮结束后停止，且不再发起下一次模型请求

#### Scenario: 预算耗尽时停止
- **WHEN** 累计消耗达到配置的预算上限
- **THEN** 循环停止，且停止原因为预算耗尽

#### Scenario: 截止期到达时停止
- **WHEN** 当前时刻超过本次会话的截止期
- **THEN** 循环停止，且停止原因为截止期到达

#### Scenario: 终止原因可被读取
- **WHEN** 循环结束后读取会话结果
- **THEN** 结果中带有明确的三选一终止原因

### Requirement: 每轮 MUST 留下可被程序读取的产出

每次模型请求与每次工具执行 SHALL 产生一条结构化记录（轮次序号、角色、内容或调用结果）。断言 MUST NOT 依赖日志文本。

#### Scenario: 一次工具调用产生两条记录
- **WHEN** 模型在一轮中请求一次工具调用且该调用成功
- **THEN** 会话记录中出现该轮的模型响应与对应的工具结果各一条

#### Scenario: 记录带有轮次序号
- **WHEN** 一次会话跨越多轮
- **THEN** 每条记录都带轮次序号，且同轮记录的序号相同

### Requirement: 同一轮内的工具调用 MUST 按模型给出的顺序串行执行

同一轮内模型给出的多个工具调用 SHALL 按其在响应中的顺序依次执行，MUST NOT 并发执行。

#### Scenario: 同一轮两个工具调用的顺序
- **WHEN** 模型在同一轮返回工具调用 A 与 B
- **THEN** 记录中 A 的结果先于 B 的结果出现

#### Scenario: 前一次调用的结果对后一次调用可见
- **WHEN** 模型在同一轮依次请求工具调用 A 与 B
- **THEN** B 执行时 A 的副作用已经生效
