## Why

现在有两件相关但不是一回事的事：

- **批量派发**（`--tasks`）把一行行提示交给同进程里的 Worker——它省事，但一个卡住的工具、一次
  OOM、一个把进程带走的 bug 会连累整批；
- **分叉**（`--fork`）让人能在同一进程里试两条路。

缺的是第三种：**把一件子任务交给独立进程，各自带自己的预算，只把"结论 + 证据 + 用量"收回来**。
长时间的研究型子任务、会跑很久的命令、以及"我不想让它污染我的上下文"这类需求，都要它。

ROADMAP 对这条的要求写得很明确：**先交付设计**（进程模型 / 预算切分 / 结果回收 / 失败传播 /
停机语义），与 zoo-framework#248 的结论一致之后再实现。所以这个变更把设计写下来，
并把**不依赖框架**的那部分真的做出来——剩下的如实标注为"等框架"。

## What Changes

**A 组 · 进程模型（新增 `src/subagent.py`）**

- 一个子任务 = 一个**独立进程**：`python src/main.py -p <任务> --session <子会话> --root <仓库>`
- 它的 cwd 指向一个**临时目录**，于是框架的状态文件天然隔离（`picklePath` 是 cwd 相对的），
  父子两个进程不会互相覆盖同一个 pickle
- 子进程的权限门是**它自己的**，默认失败关闭：父进程放行过什么，一点都漏不过去

**B 组 · 结果回收：只回三样**

- 让子进程以 `--json` 跑，父进程解析它的事件流（那份契约本项目一直按字节守着）：
  **结论** = 最后一条模型响应；**证据** = 用过的工具序列 + 终止原因；**用量** = tokens / 轮数 / 墙钟
- MUST NOT 把子会话的记录灌回父上下文——那正是要避免的上下文爆炸。记录都留着，要翻自己翻

**C 组 · 失败传播与停机**

- 子进程失败（非零退出、超时、没有结论）→ 变成一条**工具失败观察**回灌给模型，
  父会话不受影响；观察里带上退出码与子进程 stderr 的尾部
- 父被取消或超时 → 子进程 MUST 被结束，不留孤儿

**D 组 · 预算切分（做到哪一步，说清楚）**

- 现在给的是**显式上界**：token 预算与墙钟上限由父指定（`--budget` / `--timeout`），子进程自己守
- **没做**的是跨进程的共享预算池与实时扣减：那需要框架层配合（#248），本变更不假装有

**E 组 · 入口（`src/cli.py`）**

- `--subagent` 打开 `subagent(task, ...)` 工具（显式开关：它会起进程）

## Capabilities

### Added Capabilities

- `subagent`：进程模型、结果回收的三样、失败传播、停机、预算上界（以及明确没做的那部分）

### Added Requirements（并入既有能力）

- `cli-interface`：SHALL 提供开启子 agent 的开关；子进程失败 MUST 收敛成观察而不是拖垮父会话

## Impact

- 新增 `src/subagent.py`；`src/cli.py`（一个开关与装配）
- `tests/test_subagent.py`（新，端到端跑**真的子进程**）
- 两份 README 增"子 agent"一节（含"预算只到上界"这句实话）；ROADMAP #43 移出 Next
- 不新增依赖；不修改 zoo-framework

## Non-goals

- **不做共享预算池**：见 D 组。写清楚比假装有更值
- 不做子 agent 的嵌套调用（子进程不带 `--subagent`）：两层的复杂度现在换不来什么
- 不做结果流式回传（父等子跑完）：先要"能收回来"，中途进度是下一步
- 不做跨机器的分布式执行：那是另一条产品线
