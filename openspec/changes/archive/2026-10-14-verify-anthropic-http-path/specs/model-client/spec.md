## ADDED Requirements

### Requirement: 缺少凭据 MUST 在装配阶段失败，MUST NOT 推迟到首次请求

构造真实提供方客户端时，若既没有显式凭据、也没有任何提供凭据的环境变量，SHALL 立即失败，
并给出一行**可操作的**说明（该设哪个环境变量）。MUST NOT 等到第一次请求才失败——
那时使用者看到的是"跑到一半的调用失败"，而真正该做的事（设密钥）得自己猜。

凭据来源 SHALL 包含各提供方的合法配置途径（例如 Bedrock / Vertex 的环境变量），
MUST NOT 因为它们不走常见的那一个变量而误报。

#### Scenario: 缺凭据时装配即失败
- **WHEN** 没有任何凭据来源就构造客户端
- **THEN** 立即抛错，且错误信息里指明该设置的环境变量

#### Scenario: 装配失败时不发任何请求
- **WHEN** 以缺凭据的方式跑一次命令行
- **THEN** 进程在发出任何模型请求之前就退出

#### Scenario: 其它合法凭据途径不被误报
- **WHEN** 设置了该提供方的其它凭据环境变量
- **THEN** 构造成功，MUST NOT 报"没有密钥"

### Requirement: Anthropic 实现的真实 HTTP 路径 SHALL 有与另一条同等的自动化验证

该实现的 HTTP 往返（请求编码、SSE 事件解析、状态码分类）SHALL 有**不依赖真实厂商**的自动化验证：
以真的 SDK 指向一个本地说该协议的服务，覆盖整条调用、流式调用（含分片工具输入）与错误状态码。

SHALL 有断言证明 SDK 自带的重试是关闭的（一次失败只产生一次请求）——
否则两层重试叠加，退避时间既解释不了也观测不到。

#### Scenario: 整条调用经真 SDK 往返
- **WHEN** 客户端经真 SDK 调用本地服务
- **THEN** 文本、工具调用与用量都被正确归一化

#### Scenario: 流式分片工具输入被拼回
- **WHEN** 服务以分片形式发送工具输入
- **THEN** 收尾时的工具调用带有完整的输入对象

#### Scenario: 限流走同一条分类
- **WHEN** 服务返回限流
- **THEN** 抛出可重试的分类

#### Scenario: 只发一次请求
- **WHEN** 服务以限流回应且未配置我们自己的重试
- **THEN** 服务只收到一次请求
