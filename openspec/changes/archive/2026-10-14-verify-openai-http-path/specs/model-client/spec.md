## ADDED Requirements

### Requirement: OpenAI 兼容实现的真实 HTTP 路径 MUST 有可复现的自动化验证

该实现的 HTTP 往返（请求编码、SSE 逐行读、状态码分类、超时）SHALL 有**不依赖真实厂商**的
自动化验证：以一个本地最小服务复现协议，覆盖整条调用、流式调用与错误状态码。

MUST NOT 只靠注入的假传输来证明这条路径可用——那证明的是映射，不是传输。

#### Scenario: 整条调用经真实传输往返
- **WHEN** 客户端指向一个本地实现该协议的服务并做整条调用
- **THEN** 文本与工具调用被正确解析（含参数由 JSON 字符串转成对象）

#### Scenario: 流式调用经真实传输往返
- **WHEN** 服务按 SSE 逐行返回文本增量与分片工具调用
- **THEN** 增量逐段交出，工具调用在收尾时被拼成完整的一次调用

#### Scenario: 错误状态码走同一条分类
- **WHEN** 服务返回限流状态码
- **THEN** 客户端抛出可重试的分类，且配了重试层时会重试并成功

#### Scenario: 命令行端到端
- **WHEN** 用命令行把提供方指向该本地服务并跑一条提示
- **THEN** 会话完整跑通，工具调用经权限门执行

#### Scenario: 请求形状可被断言
- **WHEN** 检查服务收到的请求
- **THEN** 系统提示在首条消息、工具声明是函数外壳、流式请求带流式标记
