## 路上抓到的两件事

- [x] D1 **同一份剧本在两条路上给出不同答案**：剧本原先是"非流式形状"，而**会话优先走流式**，
  于是第一条会话就看见空响应（工具调用没了）。这不是假 provider 的小毛病——它暴露的是
  "两条路必须由同一份输入编出来"这条纪律；现在服务端两种回答都由同一条剧本编，用例里还留了一条
  断言两条路一致。**注意：这也说明真正被会话用到的是流式路径**，所以 B4 那条端到端覆盖的是 SSE。
- [x] D2 **受限环境跳过并写明原因**：外层沙箱不允许 `bind` 回环端口，于是这组用例在那里跳过
  （`skipif` + 明确 reason），而不是失败。CI 与普通开发机都跑得到；本机用一次放行运行验过全绿。
