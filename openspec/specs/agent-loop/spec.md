# agent-loop Specification

## Purpose
定义 agent 循环的推进方式与终止条件。该能力要求一次会话能从单个 prompt 出发，反复「问模型 → 执行工具 → 回灌观察」直到命中终止条件，并在每一轮留下**可被程序读取**的产出——使运行过程可断言，而不是只能端到端目视。

## Requirements

### Requirement: 循环 MUST 在终止条件之一命中时停止

循环 SHALL 在三类终止条件之一命中时停止：预算耗尽、截止期到达、模型不再请求工具调用。MUST NOT 在无终止条件的情况下无限推进。

#### Scenario: 模型不再请求工具时自然停止
- **WHEN** 模型返回的响应不含任何工具调用
- **THEN** 循环在该轮结束后停止，且不再发起下一次模型请求

#### Scenario: 预算耗尽时停止
- **WHEN** 累计消耗达到配置的预算上限
- **THEN** 循环停止，且停止原因为预算耗尽

#### Scenario: 截止期到达时停止
- **WHEN** 当前时刻超过本次会话的截止期
- **THEN** 循环停止，且停止原因为截止期到达

#### Scenario: 终止原因可被读取
- **WHEN** 循环结束后读取会话结果
- **THEN** 结果中带有明确的三选一终止原因

### Requirement: 每轮 MUST 留下可被程序读取的产出

每次模型请求与每次工具执行 SHALL 产生一条结构化记录（轮次序号、角色、内容或调用结果）。断言 MUST NOT 依赖日志文本。

#### Scenario: 一次工具调用产生两条记录
- **WHEN** 模型在一轮中请求一次工具调用且该调用成功
- **THEN** 会话记录中出现该轮的模型响应与对应的工具结果各一条

#### Scenario: 记录带有轮次序号
- **WHEN** 一次会话跨越多轮
- **THEN** 每条记录都带轮次序号，且同轮记录的序号相同

### Requirement: 同一轮内的工具调用 MUST 按模型给出的顺序串行执行

同一轮内模型给出的多个工具调用 SHALL 按其在响应中的顺序依次执行，MUST NOT 并发执行。

#### Scenario: 同一轮两个工具调用的顺序
- **WHEN** 模型在同一轮返回工具调用 A 与 B
- **THEN** 记录中 A 的结果先于 B 的结果出现

#### Scenario: 前一次调用的结果对后一次调用可见
- **WHEN** 模型在同一轮依次请求工具调用 A 与 B
- **THEN** B 执行时 A 的副作用已经生效

### Requirement: 会话事件 MUST 经框架 topic 发布，终止 MUST 以事件送达

循环 SHALL 把会话事件（``model_response`` / ``tool_result``）发布到事件 topic，SHALL 把终止
以终止 topic 上的一条事件送达；事件顺序 MUST 与记录顺序一致。消费者 SHALL 通过**订阅**获得
事件，MUST NOT 靠轮询记录或 diff 存储来重建事件流。没有订阅者时发布 MUST 是空操作。

#### Scenario: 事件顺序与记录顺序一致
- **WHEN** 一轮里发生多次会话事件
- **THEN** 订阅者收到的事件顺序与记录顺序一致

#### Scenario: 终止经事件送达
- **WHEN** 会话走到终止条件
- **THEN** 订阅者收到一条携带终止原因的终止事件，且调用方无需轮询会话状态即可得知已停止

#### Scenario: 没有订阅者时行为不变
- **WHEN** 没有任何消费者订阅事件
- **THEN** 发布是空操作，会话记录与终止结果与有订阅者时一致

### Requirement: 会话 MUST 持有显式阶段，且 MUST 可被取消

会话状态 SHALL 记录当前阶段（``thinking`` / ``tools_pending`` / ``stopped``），阶段变化
MUST 在相关事件送达之前落定。取消 SHALL 以状态位表达：置位后循环 MUST 在下一个边界停止并把
终止原因记为 ``cancelled``，MUST NOT 再派发尚未派发的调用、MUST NOT 再请求模型；已经派发的
调用 MUST 不受影响并照常完成。

#### Scenario: 阶段可读且随事件更新
- **WHEN** 会话处于某一步（等模型 / 等工具 / 已终止）
- **THEN** 读会话状态得到的阶段与该步一致，且订阅者在该步的事件里读到的阶段已经更新

#### Scenario: 取消在下一个边界生效
- **WHEN** 运行中请求取消
- **THEN** 循环停止，终止原因为 ``cancelled``，且此后不再派发调用、不再请求模型

#### Scenario: 取消不中断已派发的调用
- **WHEN** 一次调用已经派发出去后才请求取消
- **THEN** 该调用照常完成并留下观察，取消只影响尚未派发的部分
