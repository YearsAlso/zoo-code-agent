# model-client Specification

## Purpose
定义模型提供方的接入契约，使循环逻辑不依赖任何具体提供方。该能力要求测试与 CI 在**没有任何 API 密钥**的情况下跑通全链路，同时让真实提供方的实现以可选依赖的形式存在、且缺失时大声失败。
## Requirements
### Requirement: 模型调用 MUST 经统一契约

循环 MUST 只通过 `ModelClient` 契约发起模型调用，MUST NOT 直接 import 任何提供方 SDK。契约的输入 SHALL 为消息序列与工具声明，输出 SHALL 为「文本内容 + 工具调用列表」。

#### Scenario: 更换实现不改动循环
- **WHEN** 以另一个 ModelClient 实现运行循环
- **THEN** 循环的代码无任何改动

#### Scenario: 循环不直接依赖提供方 SDK
- **WHEN** 检查循环所在模块的导入
- **THEN** 其中不出现任何提供方 SDK 的 import

### Requirement: 脚本化实现 MUST 使 CI 在无密钥环境下可跑

SHALL 提供一个按预设脚本返回响应的 `ModelClient` 实现。它 MUST NOT 发起任何网络请求。默认安装即包含它。

#### Scenario: 无密钥环境下跑通全链路
- **WHEN** 在未设置任何模型 API 密钥的环境中运行全部测试
- **THEN** 循环、工具执行与会话持久化的端到端用例全部通过

#### Scenario: 脚本化实现不发网络请求
- **WHEN** 使用脚本化实现执行一次完整循环
- **THEN** 期间没有任何出站网络请求

#### Scenario: 脚本耗尽时的行为明确
- **WHEN** 循环请求的次数超过脚本预设的响应条数
- **THEN** 抛出错误指明脚本已耗尽，MUST NOT 静默返回空响应

### Requirement: 真实提供方 MUST 为可选依赖

真实提供方的实现 SHALL 依赖 `anthropic` 包，该包 MUST NOT 进入默认安装。

#### Scenario: 默认安装不含提供方 SDK
- **WHEN** 以默认方式（不含 extras）安装本仓库
- **THEN** `anthropic` 未被安装

#### Scenario: 缺少 extras 时大声失败
- **WHEN** 在未安装 `anthropic` 的环境中选择真实提供方
- **THEN** 抛出错误并指明需要安装的 extras 名称，MUST NOT 静默回退到脚本化实现

### Requirement: 流式 MUST 是可选能力，且两条路的产出 MUST 同构

模型层 SHALL 在 ``ModelClient.complete`` 之外提供**可选**的流式能力，形如
``stream(messages, tools)``，逐条交出 ``TextDelta`` / ``ResponseDone``。声明为可选是刻意的：
既有实现（含本仓库之外的）MUST NOT 因为这次变更而失效。

走流式的实现 SHALL 在正文有增量时**立刻**交出它，MUST NOT 攒到最后一次性给出；
收尾 SHALL 给出与 ``complete`` 同构的 ``ModelResponse``。流结束时没有收尾条目 MUST 报错，
MUST NOT 被当成"模型没话说"。

未实现流式的客户端 MUST 仍能被正常调用。

#### Scenario: 拿到增量是即时的
- **WHEN** 一次流式调用产生多段正文
- **THEN** 调用方在流结束之前就能逐段拿到它们

#### Scenario: 收尾响应与整条调用同构
- **WHEN** 一次流式调用结束
- **THEN** 收尾条目里的响应与同一输入下 ``complete`` 的产物同构（正文、工具调用、用量都在）

#### Scenario: 流没有收尾就报错
- **WHEN** 流迭代完了却没有收尾条目
- **THEN** 抛错，MUST NOT 返回空响应

#### Scenario: 不实现流式的客户端照常可用
- **WHEN** 用一个只实现 ``complete`` 的客户端跑一轮
- **THEN** 会话正常推进，行为与引入流式之前一致

### Requirement: 模型错误 MUST 有分类，可重试性 MUST 由分类决定

模型层 SHALL 把调用失败分类（至少区分：限流、临时故障、鉴权失败、请求错误、依赖缺失），
并 SHALL 提供"这个错误可不可以重试"的判定。判定 MUST 是**失败关闭**：只有明确认识为临时的
错误才可重试，认不出来的一律不可重试——确定性失败（参数错、模型名错、权限错）重试必然再失败，
白白等上几秒还多花几次请求。

#### Scenario: 限流与临时故障可重试
- **WHEN** 一次调用因限流或临时故障失败
- **THEN** 判定为可重试

#### Scenario: 鉴权失败与请求错误不可重试
- **WHEN** 一次调用因鉴权失败（401/403）或请求错误（其余 4xx）失败
- **THEN** 判定为不可重试，MUST NOT 产生等待

#### Scenario: 认不出来的错误不可重试
- **WHEN** 一次调用以没有分类的异常失败
- **THEN** 判定为不可重试

### Requirement: 重试 MUST 退避、有上限，且流式在交出增量之后 MUST NOT 重试

重试 SHALL 采用退避（指数增长、有上限、带抖动），重试次数 SHALL 是"最多尝试几次"且有限。
每次重试 SHALL 可被观测到（第几次、为什么、等多久），MUST NOT 静默等待。

流式调用在**已经交出任何增量之后** MUST NOT 重试：重试会让同一段正文出现两次，而那看起来像
成功了——比失败更糟。还没交出增量时 MAY 重试。

#### Scenario: 退避且次数有上限
- **WHEN** 一次调用持续以可重试的错误失败
- **THEN** 尝试次数不超过配置上限，且两次尝试之间的等待随次数增长

#### Scenario: 不可重试的错误不等待
- **WHEN** 一次调用以不可重试的错误失败
- **THEN** 立刻抛出，MUST NOT 有任何等待

#### Scenario: 流式交出增量后不再重试
- **WHEN** 一次流式调用已经交出正文增量后失败
- **THEN** 直接失败，MUST NOT 重试

#### Scenario: 流式在交出增量前可以重试
- **WHEN** 一次流式调用在交出任何增量之前失败
- **THEN** 按同一套退避重试

#### Scenario: 关掉重试后行为与不包这一层一致
- **WHEN** 重试次数配置为 0 或不包装重试
- **THEN** 一次失败就是一次失败，抛出的错误与直接调用模型层时相同

### Requirement: SHALL 提供 OpenAI 兼容端点实现，且 MUST 只依赖标准库

模型层 SHALL 提供一个面向 OpenAI 兼容 ``/chat/completions`` 协议的实现，使使用者**走配置**
即可换模型或换端点（自建 vLLM、网关、各类中转服务），MUST NOT 需要改代码。

该实现 MUST 只依赖标准库，MUST 同样支持整条与流式两条路，且 MUST 复用既有契约
（``ModelClient`` / ``StreamingModelClient``）与既有分类——**循环、渲染、重试三层 MUST NOT
为了接它而改动**。为此 HTTP 传输 SHALL 可注入，使映射与流式收尾能在没有网络的环境里被验证。

错误 MUST 经分类映射后抛出：限流与临时故障可重试，鉴权与请求错误不可重试。

#### Scenario: 走配置换端点
- **WHEN** 指定提供方为 OpenAI 兼容并给出端点地址
- **THEN** 会话通过该端点跑通，MUST NOT 需要改任何代码

#### Scenario: 工具调用参数被正确解析
- **WHEN** 端点返回一次工具调用（其参数在协议里是 JSON **字符串**）
- **THEN** 解析成参数对象交给工具层；MUST NOT 原样把字符串当参数

#### Scenario: 流式增量与分片工具调用
- **WHEN** 端点以流式返回文本增量与分片到达的工具调用
- **THEN** 文本增量逐段交出，工具调用按序拼成完整的一次调用，收尾给出与整条调用同构的响应

#### Scenario: 错误按分类抛出
- **WHEN** 端点返回 429 或 5xx
- **THEN** 抛出可重试的分类；返回 401/403 或其它 4xx 时抛出不可重试的分类

#### Scenario: 不联网也能验证
- **WHEN** 用注入的假传输跑一次整条调用与一次流式调用
- **THEN** 两条路都完整跑通，MUST NOT 发起真实网络请求

### Requirement: OpenAI 兼容实现的真实 HTTP 路径 MUST 有可复现的自动化验证

该实现的 HTTP 往返（请求编码、SSE 逐行读、状态码分类、超时）SHALL 有**不依赖真实厂商**的
自动化验证：以一个本地最小服务复现协议，覆盖整条调用、流式调用与错误状态码。

MUST NOT 只靠注入的假传输来证明这条路径可用——那证明的是映射，不是传输。

#### Scenario: 整条调用经真实传输往返
- **WHEN** 客户端指向一个本地实现该协议的服务并做整条调用
- **THEN** 文本与工具调用被正确解析（含参数由 JSON 字符串转成对象）

#### Scenario: 流式调用经真实传输往返
- **WHEN** 服务按 SSE 逐行返回文本增量与分片工具调用
- **THEN** 增量逐段交出，工具调用在收尾时被拼成完整的一次调用

#### Scenario: 错误状态码走同一条分类
- **WHEN** 服务返回限流状态码
- **THEN** 客户端抛出可重试的分类，且配了重试层时会重试并成功

#### Scenario: 命令行端到端
- **WHEN** 用命令行把提供方指向该本地服务并跑一条提示
- **THEN** 会话完整跑通，工具调用经权限门执行

#### Scenario: 请求形状可被断言
- **WHEN** 检查服务收到的请求
- **THEN** 系统提示在首条消息、工具声明是函数外壳、流式请求带流式标记

### Requirement: 缺少凭据 MUST 在装配阶段失败，MUST NOT 推迟到首次请求

构造真实提供方客户端时，若既没有显式凭据、也没有任何提供凭据的环境变量，SHALL 立即失败，
并给出一行**可操作的**说明（该设哪个环境变量）。MUST NOT 等到第一次请求才失败——
那时使用者看到的是"跑到一半的调用失败"，而真正该做的事（设密钥）得自己猜。

凭据来源 SHALL 包含各提供方的合法配置途径（例如 Bedrock / Vertex 的环境变量），
MUST NOT 因为它们不走常见的那一个变量而误报。

#### Scenario: 缺凭据时装配即失败
- **WHEN** 没有任何凭据来源就构造客户端
- **THEN** 立即抛错，且错误信息里指明该设置的环境变量

#### Scenario: 装配失败时不发任何请求
- **WHEN** 以缺凭据的方式跑一次命令行
- **THEN** 进程在发出任何模型请求之前就退出

#### Scenario: 其它合法凭据途径不被误报
- **WHEN** 设置了该提供方的其它凭据环境变量
- **THEN** 构造成功，MUST NOT 报"没有密钥"

### Requirement: Anthropic 实现的真实 HTTP 路径 SHALL 有与另一条同等的自动化验证

该实现的 HTTP 往返（请求编码、SSE 事件解析、状态码分类）SHALL 有**不依赖真实厂商**的自动化验证：
以真的 SDK 指向一个本地说该协议的服务，覆盖整条调用、流式调用（含分片工具输入）与错误状态码。

SHALL 有断言证明 SDK 自带的重试是关闭的（一次失败只产生一次请求）——
否则两层重试叠加，退避时间既解释不了也观测不到。

#### Scenario: 整条调用经真 SDK 往返
- **WHEN** 客户端经真 SDK 调用本地服务
- **THEN** 文本、工具调用与用量都被正确归一化

#### Scenario: 流式分片工具输入被拼回
- **WHEN** 服务以分片形式发送工具输入
- **THEN** 收尾时的工具调用带有完整的输入对象

#### Scenario: 限流走同一条分类
- **WHEN** 服务返回限流
- **THEN** 抛出可重试的分类

#### Scenario: 只发一次请求
- **WHEN** 服务以限流回应且未配置我们自己的重试
- **THEN** 服务只收到一次请求

### Requirement: 错误分类 MUST 覆盖所用 SDK 的完整异常词汇表

分类依据 SHALL 覆盖该 SDK 实际会抛出的异常种类；"认不出来"的集合 MUST 是**显式列出的小白名单**
（基类、响应形状校验、本地凭据文件之类），并由用例守住——多一个都不行。

理由是可算的：没被覆盖的临时故障会掉进"认不出来 → 不重试"那一侧，
于是一次本该自愈的过载被判成任务失败。

#### Scenario: 临时故障的每一类都被认出来
- **WHEN** 逐一取该 SDK 的临时故障异常（连接、超时、截止期、过载、不可用、服务端错误、重试类）
- **THEN** 都被分类成可重试的临时故障

#### Scenario: 鉴权类都被认出来
- **WHEN** 逐一取鉴权相关异常（鉴权、权限、凭据）
- **THEN** 都被分类成不可重试的鉴权失败

#### Scenario: 认不出来的只有白名单里那些
- **WHEN** 遍历该 SDK 的全部异常类
- **THEN** 未被分类的集合恰好等于白名单，多一个都会让用例失败
